# 行动选项按钮

很多预设会让模型在回复末尾给出一组“行动选项”。silly-tg 能把它们解析出来，在 Telegram 里变成一条带数字按钮的消息：点一下，对应的选项文字就作为你的下一条消息发出。

## 效果

- 正文里的选项块被去掉，不重复显示。
- 回复下面多一条消息，列出完整的编号选项，下方是 `1` `2` `3`…… 数字按钮（每行 4 个）。
- 点按钮后这条消息变成“已选择 N：……”，选项文字被发给角色，开始生成。
- 只有**最新一条回复**的选项有效。你自己打字、`/regen`、切换角色/聊天之后，旧按钮会提示已过期。
- 回复被停止、没有命中任何规则、选项数为 0 或超过 12 个时，回复照常发送，没有按钮。

## 内置规则

| 名称 | 匹配的写法 |
|---|---|
| `SUOT` | `<SUOT>` 和 `</SUOT>` 之间，每行一个编号选项（`1. xxx`，也认 `1、`、`1)`、`（1）`、`A.`） |
| `标题+编号列表` | 回复末尾的 `【行动选项】` / `行动选项：` 之类标题，后面跟编号列表 |

样例见 [`samples/suot.txt`](samples/suot.txt)。

## 适配你的预设

在 `config.json` 同目录新建 `choice-rules.json`（参考 [`choice-rules.example.json`](../choice-rules.example.json)）。改完**不用重启**，下一条回复就生效。你的规则排在内置规则之前，第一条解析出 1–12 个选项的规则生效。

```json
[
  {
    "name": "我的预设",
    "block": "<options>([\\s\\S]*?)</options>",
    "item": "^\\s*[-•]\\s*(.+?)\\s*$",
    "htmlSelector": "options"
  }
]
```

| 字段 | 说明 |
|---|---|
| `name` | 规则名，日志里显示。 |
| `block` | 正则（JSON 里反斜杠要写两个）。在**原始消息**里找选项块，**第 1 个捕获组**是块里的内容。大小写不敏感。 |
| `item` | 正则。对块内**每一行**匹配，**第 1 个捕获组**是选项文字；行首的编号、符号放在捕获组外面。不匹配的非空行会并入上一个选项（处理折行）。 |
| `htmlSelector` | 可选。选项块在渲染后 HTML 里的标签名（小写），用来把它从发给 Telegram 的正文里去掉。 |

“原始消息”指 ST 里点“编辑消息”看到的文字，不是屏幕上渲染后的样子。

### 先离线试规则

把一条回复的原始文字存成文本文件，然后：

```bash
pnpm choices:test choice-rules.json my-sample.txt   # 带你的规则
pnpm choices:test - docs/samples/suot.txt            # 只用内置规则
```

它会打印命中的规则、解析出的选项和去掉选项块后的正文；没命中退出码为 1，规则文件有问题为 2。

### 让 AI 帮你写规则

仓库里的 [`skills/silly-tg-choice-rules`](../skills/silly-tg-choice-rules/SKILL.md) 是给 Claude Code 等工具用的 skill：贴一段你的预设产生的回复，它会写出规则、跑 `pnpm choices:test` 验证，再给你结果确认。

## 常见问题

- **按钮没出现**：看日志里有没有 `解析到行动选项`。没有就是规则没命中，用 `pnpm choices:test` 对着真实回复试。
- **正文里选项还在**：ST 会把未知标签（如 `<SUOT>`）去掉只留内容，并把编号行渲染成列表。插件会尝试去掉末尾与选项对应的列表，去不干净时宁可保留正文。可以给规则补 `htmlSelector`，或让预设把选项放在回复最后。
- **选项太长**：消息里最多显示每项 300 字，但点按钮发出去的是完整文字。
- **规则写错**：非法正则会在日志里警告并被跳过，不影响其他规则。
