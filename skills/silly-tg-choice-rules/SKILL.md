# silly-tg 行动选项规则

silly-tg 把回复末尾的行动选项解析成 Telegram 按钮。格式因预设而异，所以用 `choice-rules.json` 里的规则描述。字段含义见 `docs/choices.md`。

## 流程

1. **拿到真实样例。** 让用户提供一条真实回复的**原始文本**（ST 里“编辑消息”看到的内容，包含标签）。只有提示词没有输出样例时，让用户先在 ST 里生成一条。不要凭提示词猜格式，模型实际输出常和提示词描述有出入。
2. **先试内置规则。** 把样例存成临时文件，运行 `pnpm choices:test - <样例文件>`。命中且选项个数正确就结束，不需要写规则。
3. **写规则。** 在 `config.json` 同目录的 `choice-rules.json`（没有就新建，参考 `choice-rules.example.json`）里加一条：
   - `block`：先写能框住整个选项区的正则，第 1 个捕获组放块内内容。优先用成对标签；没有标签就用固定标题加末尾锚点 `$`。
   - `item`：对块内一行的正则，第 1 个捕获组只放选项文字，编号和符号放捕获组外。
   - `htmlSelector`：块是标签包裹时填标签名（小写）。
   - JSON 里正则的反斜杠要写成 `\\`。
4. **自测。** 运行 `pnpm choices:test choice-rules.json <样例文件>`，核对：个数对、每项文字完整、没有多出编号或符号、去掉选项块后正文干净。再用一条**没有选项**的回复试一次，确认不会误命中。
5. **报告。** 把规则、自测输出贴给用户确认。提醒：改完不用重启，下一条回复生效；日志里出现 `解析到行动选项` 说明在线上生效。

## 注意

- 不要改内置规则（`src/server/choices.ts`），用户规则排在前面即可。
- 一个预设有多种写法时，写多条规则，各自独立。
- 选项数必须在 1–12 之间，否则整条规则不生效。
- 样例里的内容可能是用户的私人对话，只用来写规则，不要写进仓库。
